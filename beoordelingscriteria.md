# Beoordelingscriteria voor ingeleverd werk CSD2

## Noodzakelijke voorwaarden
**Indien er niet aan onderstaande voorwaarden** _(Git, ontwerp en uitwerking, code en documentatie)_ **is voldaan, wordt het ingeleverde werk niet nagekeken. Na overleg kan het werk worden gecorrigeerd voor de gestelde deadline of worden herkanst** _(laat de docenten per mail weten wanneer het werk opnieuw is aangeleverd)_.

### Git
Code en documentatie worden ingeleverd via Git. Voorwaarden:
- De folderstructuur in de git repository volgt de structuur uit de weergave hieronder.
- Uit de commit history van de git repository blijkt een goede git workflow.

```
CSD/
|-- CSD2a/
    |--sessie1/
    |--sessie2/
    |--...
    |--eindopdracht/
|-- CSD2b/
    |--sessie1/
    |--sessie2/
    |--...
    |--eindopdracht/
|-- CSD2c/
    |--...    
    |--eindopdracht/
|-- CSD2d/
    |--...
    |--eindopdracht/
```

### Ontwerp
Voorwaarden aan het ontwerp van het project, het ontwerp:
- ... is goedgekeurd;
- ... is als uitgangspunt genomen bij de verdere uitwerking van het project; _(Voorschreidende inzichten kunnen leiden tot aanpassingen aan het ontwerp, mits dit onderbouwd kan worden.)_ Projectdocumentatie moet dan worden aangepast.
- ... voldoet aan de project voorwaarden _(zie de opdracht omschrijving én de beoordelingscriteria van het desbetreffende blok)_.

###  Eindartefact
Voorwaarden aan de applicatie, de applicatie:
- ... bevat de vereiste elementen _(zie de opdracht omschrijving én de beoordelingscriteria van het desbetreffende blok)_.
 - ... bevat duidelijke gebruikers-interactie _(indien van toepassing)_;
 - ... werkt en 'klinkt';
 - ... crasht niet;
 - ... vangt onjuiste input van de gebruiker af en geeft duidelijke foutmeldingen.

 ### Documentatie
_Per blok gelden andere voorwaarden voor de documentatie, zie de opdrachtbeschrijving en de beoordelingscriteria van het desbetreffende blok._

### Code
Voorwaarden aan de code; de code is begrijpelijk voor anderen:
  - De structuur is duidelijk.
  - De code is voorzien van helderdere en relevante comments.
  - De code bevat geen 'uitgecommente' irrelevante code.
  - Er is sprake van een heldere verklarende naamgeving binnen de code _(zoals variabelen, functies, classes)_ alsmede voor files.




## Beoordeling
Het project kan gepresenteerd worden tijdens de presentatie les van het blok, wanneer er is voldaan aan de noodzakelijke voorwaarden _(zie hierboven onder **'Noodzakelijke voorwaarden'** - Git, Ontwerp, Eindartefact, Documentatie en Code)_.

De beoordeling wordt gebaseerd op:
- (25%) de presentatie
- (75%) documentatie én code

Voor de exacte beoordelingscriteria, zie de beoordelingscriteria van het desbetreffende blok.
